# CR-002 - Presentación del producto

Este pedido de cambio introduce el concepto de **Presentación** (ej.: `1L`, `pack`, `500ml`), que describe la forma comercial en la que se ofrece un producto.

Nos encontramos con un caso similar al de SuperLínea: una Presentación tiene identidad y ciclo de vida propios, puede existir sin un Producto particular y puede asociarse a múltiples productos, por lo que requiere un ABMC propio. Por estos motivos, modelamos a **Presentación como una nueva entidad** (Aggregate Root), no como Value Object.

En cuanto a los agregados, `Presentacion`, `Producto`, `Marca` y `Linea` poseen identidad y ciclo de vida independientes, y deben poder crearse, modificarse y consultarse por separado. Por lo tanto, cada uno es raíz de su propio agregado.

Se agregan al dominio los comportamientos de gestión de Presentación y se modifica el comportamiento de gestión de Producto: todo producto deberá tener una Presentación asociada.

## Nuevas reglas de negocio

- Cada Producto deberá pertenecer a / tener asociada una, y solo una, Presentación. Esta regla vivirá en la orquestación de alta/modificación de Producto, validando que la Presentación exista y esté activa.
- No se podrá eliminar una Presentación a la que pertenezcan uno o más productos activos. Esta regla residirá en un servicio de dominio (política de eliminación).
- No podrá haber dos Presentaciones con la misma denominación (incluye registros eliminados lógicamente). Esta regla residirá en un servicio de dominio / validador, respaldada por constraint de BD.

## Historias de usuario

### Historias modificadas

Las historias “Registrar Producto” y “Modificar Producto” se ven afectadas con estos criterios:

- **CA-1:** El sistema debe permitir seleccionar una Presentación previamente registrada y activa.
- **CA-2:** La Presentación es un dato obligatorio del Producto; no se permite guardar sin seleccionarla.
- **CA-3:** Si no existen Presentaciones disponibles, el sistema debe informar que primero se debe registrar una.

### Historias nuevas

#### HU — Registrar Presentación

Como administrador de productos, quiero registrar una Presentación, para poder clasificar productos por su forma comercial (ej.: 1L, pack).

**Criterios de aceptación:**

- Se debe poder ingresar la denominación de la Presentación y una observación.
- La denominación es obligatoria; la observación no.
- El sistema debe generar un identificador para la Presentación.
- El sistema debe informar que la Presentación fue registrada correctamente.
- El sistema no debe permitir registrar una Presentación cuya denominación ya esté registrada (activa o eliminada).

#### HU — Consultar Presentaciones

Como administrador de productos, quiero consultar las Presentaciones registradas, para conocer las formas comerciales disponibles.

**Criterios de aceptación:**

- Se deben mostrar las Presentaciones registradas (al menos id y denominación).
- Se debe poder consultar la observación cuando exista.
- Si no existen Presentaciones, el sistema debe informar dicha situación (colección vacía).

#### HU — Modificar Presentación

Como administrador de productos, quiero modificar una Presentación, para mantener actualizada su información.

**Criterios de aceptación:**

- Se debe poder seleccionar una Presentación existente.
- Se debe poder modificar su denominación y observación.
- La denominación continúa siendo obligatoria.
- El identificador se mantiene.
- Los cambios se reflejan en consultas posteriores.

#### HU — Eliminar Presentación

Como administrador de productos, quiero eliminar una Presentación que ya no sea necesaria, para mantener actualizado el catálogo.

**Criterios de aceptación:**

- Se debe poder seleccionar una Presentación existente.
- Se debe solicitar confirmación antes de eliminarla (responsabilidad de UI).
- No se debe permitir eliminar una Presentación que tenga productos activos asociados.
- Si no tiene productos activos, se debe permitir eliminarla (borrado lógico).
- Una Presentación eliminada no debe estar disponible para nuevas asociaciones.

## Cambios en el dominio

- Se agrega la entidad `Presentacion` como raíz de su propio agregado.
- `Producto` sigue siendo raíz de su agregado y pasa a tener una única Presentación obligatoria.
- Una Presentación puede tener muchos Productos.
- Queda fuera de este CR la generación automática de denominación (CR-005).
- Se deja como **deuda técnica consciente** el overlap conceptual entre `Presentacion` y los campos existentes `utilizaPack` / `cantidadPorPack`: no se unifican en esta entrega.
